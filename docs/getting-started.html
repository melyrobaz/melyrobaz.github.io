Guide de démarrage

Créer son premier plugin

Objectif : produire une DLL minimale qui s’active, écrit dans le journal, affiche un toast et compte ses lancements. Tous les appels utilisés ici existent dans ember-plugin-api 0.1.0 et dans l’hôte 2.8.0.

ABI 1 Rust 2021 cdylib Windows uniquement

1. Prérequis

  • Windows x64. Le chargeur DLL n’existe que sous Windows et la DLL doit avoir la même architecture que l’hôte.
  • Une chaîne Rust stable capable de produire des cdylib. Le dépôt ne fixe ni rust-toolchain.toml ni rust-version.
  • Le SDK présent dans ember-sdk/. La crate ember-plugin-api n’est pas publiée sur crates.io dans ce dépôt : elle s’utilise par chemin.
  • FloralPlayer installé, pour tester la DLL.

Le workspace se compile

ember-sdk/Cargo.toml déclare ember-plugin-api et les plugins hello, discord et listenbrainz. Ajoutez simplement votre dossier à members, puis cargo build --release -p mon-plugin.

2. Créer le crate

Ajoutez un dossier ember-sdk/plugins/mon-plugin/ :

ember-sdk/
  Cargo.toml                 · workspace
  ember-plugin-api/
  plugins/
    mon-plugin/
      Cargo.toml
      src/
        lib.rs

ember-sdk/plugins/mon-plugin/Cargo.toml :

[package]
name = "mon-plugin"
version = "1.0.0"
edition = "2021"

[lib]
name = "mon_plugin"          # produit mon_plugin.dll
crate-type = ["cdylib"]

[dependencies]
ember-plugin-api = { path = "../../ember-plugin-api" }
serde_json = "1"

Déclarez le membre dans ember-sdk/Cargo.toml. Exemple de workspace : 

[workspace]
resolver = "2"
members = [
    "ember-plugin-api",
    "plugins/hello",
    "plugins/discord",
    "plugins/listenbrainz",
    "plugins/mon-plugin",
]

[profile.release]
opt-level = 2
lto = "thin"
strip = true

Le profil de release s’applique à tous les membres. strip = true ne supprime pas l’export ember_plugin_v1.

3. Le code minimal

ember-sdk/plugins/mon-plugin/src/lib.rs. Le type doit implémenter Default : la macro crée l’instance avec Default::default(). Aucun unsafe n’est nécessaire. 

//! Plugin d'exemple : journal, réglage persistant, toast.

use ember_plugin_api::{Host, Plugin, FLAG_DEFAULT_ON};
use serde_json::Value;

#[derive(Default)]
struct MonPlugin {
    ticks: u64,
}

impl Plugin for MonPlugin {
    fn init(&mut self, host: &Host) -> Result<(), String> {
        // La valeur vit dans plugins.mon-plugin.runs, au format JSON.
        let runs: u64 = host
            .setting("runs")
            .and_then(|s| s.trim().parse().ok())
            .unwrap_or(0)
            + 1;
        host.set_setting("runs", &runs.to_string());

        host.log(0, &format!("mon-plugin : init ({runs}e lancement)"));
        host.toast(&format!("Mon plugin est actif ({runs}e lancement)"));
        Ok(())
    }

    fn tick(&mut self, snapshot: &str, _host: &Host) {
        self.ticks += 1;

        // Environ 5 appels par seconde : une lecture tous les 80 ticks.
        if self.ticks % 80 == 0 {
            let v: Value = serde_json::from_str(snapshot).unwrap_or(Value::Null);
            let _ = (
                v["pos"].as_f64().unwrap_or(0.0),
                v["dur"].as_f64().unwrap_or(0.0),
                v["playing"].as_bool().unwrap_or(false),
            );
        }
    }

    fn event(&mut self, event: &str, host: &Host) {
        let v: Value = serde_json::from_str(event).unwrap_or(Value::Null);
        match v["type"].as_str().unwrap_or_default() {
            "track_started" => {
                host.log(
                    0,
                    &format!(
                        "mon-plugin : piste « {} — {} »",
                        v["title"].as_str().unwrap_or("?"),
                        v["artist"].as_str().unwrap_or("?")
                    ),
                );
            }
            "paused" => host.log(0, "mon-plugin : pause"),
            "resumed" => host.log(0, "mon-plugin : reprise"),
            "stopped" => host.log(0, "mon-plugin : arrêt"),
            other => host.log(1, &format!("mon-plugin : événement « {other} »")),
        }
    }

    fn shutdown(&mut self, host: &Host) {
        host.log(0, &format!("mon-plugin : shutdown après {} ticks", self.ticks));
    }
}

ember_plugin_api::declare_plugin!(
    MonPlugin,
    id = "mon-plugin",
    name = "Mon plugin",
    version = "1.0.0",
    desc = "Démonstration du contrat DLL.",
    category = "Système",
    flags = FLAG_DEFAULT_ON,
    deps = "",
);

Contraintes de la macro :

  • id, name, version, desc, category et deps doivent être des littéraux (la macro utilise concat!).
  • flags doit être une expression constante.
  • Le type du plugin doit être Default et 'static.
  • La catégorie inconnue, vide ou Système est mappée sur « Système ». Les valeurs reconnues sont Intégration, Interface, Audio et Bibliothèque.

4. Compiler

Depuis la racine du projet :

cargo build --manifest-path ember-sdk\Cargo.toml --release

La DLL est produite dans ember-sdk\target\release\mon_plugin.dll. En mode debug, remplacez --release par rien : la sortie va dans ember-sdk\target\debug\.

5. Installer la DLL

L’hôte scanne exactement deux dossiers, au démarrage seulement :

  1. <dossier de l'exécutable>\plugins — prioritaire ;
  2. %APPDATA%\Floral Player\plugins.

Le dossier de données est créé par l’hôte, mais pas le sous-dossier plugins. Créez-le et copiez la DLL : 

New-Item -ItemType Directory -Force "$env:APPDATA\Floral Player\plugins" | Out-Null
Copy-Item "ember-sdk\target\release\mon_plugin.dll" "$env:APPDATA\Floral Player\plugins\"

Tout fichier *.dll est examiné, sans scan récursif. Le nom du fichier est libre et n’influence pas l’identité du plugin, qui vient du champ id.

Ne vous fiez pas à build.ps1

ember-sdk/build.ps1 copie vers %APPDATA%\Ember Player\plugins ou vers Ember Player\plugins. Ces deux destinations ne sont pas scannées par l’hôte actuel, qui utilise %APPDATA%\Floral Player\plugins. Copiez la DLL manuellement vers l’un des deux dossiers ci-dessus.

6. Vérifier

  1. Démarrer FloralPlayer

    Avec FLAG_DEFAULT_ON, le plugin est activé au premier lancement et init s’exécute.

  2. Ouvrir Préférences → Plugins

    La ligne « Mon plugin » doit apparaître, avec la catégorie « Système ».

  3. Lire le journal

    Ouvrez %APPDATA%\Floral Player\plugins.log. Une ligne info [mon-plugin] mon-plugin : init (1e lancement) doit apparaître.

  4. Tester la persistance

    Désactivez puis réactivez le plugin : shutdown puis init sont appelés. Fermez proprement l’application, rouvrez-la : le compteur runs doit augmenter au prochain enregistrement des réglages.

Ce guide n’est pas un exemple livré

Le code ci-dessus reconstruit le plus petit plugin utile à partir du contrat réel ; il n’a pas été compilé dans le cadre de cette documentation. Ajoutez un test de chargement avant de le distribuer.
