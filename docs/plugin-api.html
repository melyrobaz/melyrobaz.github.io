API des plugins DLL

Contrat C de l’ABI v1 : une fonction d’entrée, une table de métadonnées et de fonctions, des callbacks fournis par l’hôte, et des échanges JSON. Toutes les signatures ci-dessous proviennent de ember-plugin-api/src/lib.rs.

ABI_VERSION = 1 repr(C) UTF-8 + NUL Pas de compatibilité N−1

Point d’entrée et table PluginV1

La DLL doit exporter, avec la convention d’appel C, une fonction sans argument qui renvoie un pointeur vers une table statique : 

#[no_mangle]
pub extern "C" fn ember_plugin_v1() -> *const PluginV1;

L’hôte cherche uniquement ce symbole. Aucune autre fonction d’initialisation n’est exportée : create, init, tick, etc. sont des champs de la table. 

#[repr(C)]
pub struct PluginV1 {
    pub abi_version: u32,
    pub id: *const c_char,
    pub name: *const c_char,
    pub version: *const c_char,
    pub desc: *const c_char,
    pub category: *const c_char,
    pub flags: u32,
    pub deps: *const c_char,
    pub create: Option<unsafe extern "C" fn(*const HostApi) -> *mut c_void>,
    pub destroy: Option<unsafe extern "C" fn(*mut c_void)>,
    pub init: Option<unsafe extern "C" fn(*mut c_void) -> c_int>,
    pub tick: Option<unsafe extern "C" fn(*mut c_void, *const c_char)>,
    pub event: Option<unsafe extern "C" fn(*mut c_void, *const c_char)>,
    pub shutdown: Option<unsafe extern "C" fn(*mut c_void)>,
    pub ui_command: Option<unsafe extern "C" fn(*mut c_void, *const c_char)>,
}

Flags

  • FLAG_DEFAULT_ON : active le plugin au premier lancement si aucune valeur enabled n’est déjà enregistrée. Une valeur existante l’emporte.
  • FLAG_NEEDS_RESTART : recopié dans les métadonnées, mais utilisé uniquement pour ajouter « (redémarrage requis) » au toast de bascule. L’hôte ne redémarre rien et n’interdit rien.
  • FLAG_HAS_UI : déclaré mais jamais lu. Il n’existe aucun protocole de panneau derrière ce bit.

ABI stricte

L’hôte refuse toute autre valeur que 1 avec le message ABI <n> alors que l'hôte attend 1. Les structures sont #[repr(C)] : ajouter, retirer, réordonner ou changer le type d’un champ est un comportement indéfini si la version n’est pas changée. Une évolution exige un nouvel ABI_VERSION et une nouvelle fonction d’entrée.

HostApi et wrapper Host

L’hôte fournit un ensemble de callbacks dans une structure opaque côté plugin :

#[repr(C)]
pub struct HostApi {
    pub abi_version: u32,
    pub host_ctx: *mut c_void,
    pub settings_get: Option<SettingsGet>,
    pub settings_set: Option<SettingsSet>,
    pub action: Option<Notify>,
    pub panel: Option<Notify>,
    pub toast: Option<Notify>,
    pub log: Option<LogFn>,
    pub free_string: Option<FreeString>,
}
ChampRôle
abi_versionL’hôte écrit 1. Le wrapper Rust ne le vérifie pas.
host_ctxPointeur opaque vers le pont de l’hôte. Ne jamais le conserver ni le déréférencer.
settings_getRenvoie une chaîne allouée par l’hôte, à libérer avec free_string.
settings_setÉcrit une valeur JSON pour le plugin courant.
actionEnvoie une action au cœur (JSON).
panelEnvoie des données de panneau. L’hôte les journalise, sans les rendre.
toastAffiche un toast. Texte brut, pas du JSON.
logÉcrit une ligne dans plugins.log avec un niveau.
free_stringLibère une chaîne renvoyée par settings_get.

Le wrapper Host rend ces callbacks sûrs pour l’auteur du plugin. Toutes ses méthodes sont sans unsafe.

Méthodes de Host
MéthodeComportement exact
setting(key) -> Option<String>Lit la clé de premier niveau de plugins.<id>. La valeur est du JSON sérialisé. Absente → None. Une valeur JSON null existante renvoie "null".
set_setting(key, json)Écrit la valeur. Si json n’est pas du JSON valide, la valeur est stockée comme chaîne.
action(json)Envoie une action JSON au cœur. Voir le tableau des commandes.
panel(json)L’hôte lit id, conserve le JSON complet dans Action::Panel.data, puis le journalise. Aucun rendu.
toast(text)Affiche un toast ; texte brut, pas du JSON.
log(level, text)Écrit dans plugins.log. Niveaux : 0 info, 1 debug, 2 avertissement, autre → erreur.

Pièges de settings

  • setting("a.b") cherche la clé littérale "a.b", pas un chemin a puis b.
  • set_setting("volume", "0.8") stocke le nombre 0.8 ; setting("volume") renvoie "0.8".
  • set_setting("nom", "\"salut\"") stocke la chaîne salut ; la relecture renvoie "\"salut\"", guillemets compris.
  • set_setting("nom", "salut") stocke aussi la chaîne salut, car ce n’est pas du JSON valide.
  • Une clé ou une valeur contenant un NUL fait échouer CString::new : l’appel est silencieusement ignoré.
  • set_setting n’écrit pas immédiatement sur le disque : la valeur attend le prochain save_settings.

Trait Plugin

pub trait Plugin: 'static {
    fn init(&mut self, host: &Host) -> Result<(), String> { Ok(()) }
    fn tick(&mut self, snapshot: &str, host: &Host) {}
    fn event(&mut self, event: &str, host: &Host) {}

    fn ui_command(&mut self, json: &str, host: &Host) {}

Données échangées

Snapshot de tick

{"pos":1.2,"dur":240.0,"playing":true}
  • pos : position dans le segment courant, en secondes. Relative au début d’une piste .cue.
  • dur : durée du segment courant, en secondes, ou durée de la piste hors .cue.
  • playing : vrai si l’audio est actif et non en pause.
  • Quand rien ne joue, le tick continue avec {"pos":0.0,"dur":0.0,"playing":false}.

Événements

typeChampsÉmis quand
track_startedpath, title, artist, album, posAu premier tick d’une nouvelle piste si l’état est lecture ou pause.
playedtitle, artist, album, atQuand le seuil d’écoute est atteint, une fois par piste.
paused—Transition lecture → pause.
resumed—Transition pause → lecture.
stopped—Transition lecture/pause → arrêt.
seekedposJamais émis par l’hôte actuel : aucun code ne construit cet événement.

Le seuil de played vaut min(30, (durée > 0 ? durée : 60) / 2) secondes. Les transitions pause/reprise/arrêt sont déduites au tick suivant, avec une latence pouvant atteindre 200 ms. track_started n’est pas émis à la simple ouverture d’une piste : il faut que la lecture ou la pause soit active.

Actions envoyées par le plugin

host.action(json) lit le champ type :

JSON envoyéEffet
{"type":"toast","text":"…"}Affiche un toast. Si text manque, l’hôte utilise le JSON brut comme texte.
{"type":"panel","id":"…", …}Journalisé, pas rendu.
Tout le resteTransmis à plugin_command comme commande JSON.

host.panel(json) ne passe pas par ce parseur : l’hôte extrait id et conserve le JSON complet reçu dans Action::Panel.data.

Commandes de l’interface vers le plugin

L’hôte n’envoie que deux formes, et seulement aux identifiants codés en dur discord et listenbrainz : 

{"type":"configure","app_id":"…"}   // → discord
{"type":"configure","token":"…"}    // → listenbrainz

Elles sont envoyées après chaque bascule de plugin, quand les champs d’intégration changent, et au démarrage. Un plugin tiers ne reçoit jamais de ui_command avec l’hôte actuel, même si la méthode existe dans l’ABI.

Panneaux, interface et version

  • host.panel et {"type":"panel"} n’ont aucun effet visuel : leur contenu finit dans plugins.log.
  • Il n’existe aucun slot de panneau générique, aucun formulaire de préférences par plugin et aucun ajout de menu fourni par une DLL.
  • La seule propriété d’interface modifiable par une DLL est remote-url, via {"type":"ui","key":"remote-url","value":"…"}.
  • Le seul retour visuel garanti pour un plugin tiers est sa ligne dans l’onglet Plugins et ses toasts.
  • PluginV1.version n’est jamais lu. FLAG_HAS_UI n’est jamais lu. seeked n’est jamais émis.

Règles de sûreté

  1. Ne jamais conserver HostApi.host_ctx ni un pointeur de callback au-delà de l’appel.
  2. Utiliser le Host fourni à chaque méthode ; ne pas le placer dans un static.
  3. Ne jamais bloquer dans tick, event, init ou shutdown : tout se fait sur le fil de l’interface. Utilisez un canal et videz-le dans tick.
  4. Ne pas déréférencer les *const c_char après l’appel : ils appartiennent à l’appelant.
  5. Ne pas écrire plugins.<id>.enabled : cette clé est gérée par l’hôte.
  6. Ne pas compter sur version, FLAG_HAS_UI ou ui_command pour un plugin tiers.
  7. Journaliser le détail d’un échec d’initialisation avant de renvoyer Err : le texte est perdu à la frontière C.

Ce que l’ABI ne couvre pas

  • Il n’existe pas d’en-tête C/C++ fourni. Un plugin hors Rust doit reconstruire les structures #[repr(C)] à la main.
  • Le format des données de panneau n’est pas spécifié, puisque l’hôte ne les interprète pas.
  • La politique de compatibilité future (ABI v2, dépréciation de v1) n’est pas définie dans le dépôt.
